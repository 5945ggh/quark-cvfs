# 文档写作风格

说清事实是什么、文档提出了什么观点、证据表明什么、方案或方法能做什么。语气平静、专业，让每段围绕一个读者需要理解的问题展开。

## 直接表达

- 开头先说观点、行为或结果，再解释理由、证据与适用条件。
- 用具体主语和动词说明谁做什么、保存什么、如何使用；一段说清一件事。
- 删除不提供事实、范围、依据或概念区分的免责声明和重复澄清。
- 少用层叠的“可能”“或许”“在一定程度上”。存在不确定性时，说明它来自证据、环境、未定决定还是验证缺口。
- 需要解释实际差异时再用对比，避免习惯性套用“不是 X，而是 Y”。

## 保留必要限定

省略限定会改变结论、证据适用范围或读者操作时，就保留。产品规则、权限、数据保留、费用、兼容范围和工程安全约束要写准。

区分产品目标、已确认决定、代码实现、实际验收和未来方案。原书注音与自动注音、逻辑删除与物理清理等差异影响使用时，应当明确说明。

局限放在对应方法、证据或限制段落。摘要、段首和结论只保留理解该句所需的限定。不要靠削弱语气代替缩小结论范围，也不要为了显得有力补造事实、数据、因果关系或优势。

## 修改流程

1. 判断句子承担什么作用：事实、范围、方法局限、概念区分、证据限定，还是重复澄清。
2. 删除没有增加信息的句子；将可以直接说明的范围改成正面陈述。
3. 按证据校准结论。理由不足时补已有依据或缩小结论，不在结尾追加笼统的“仍有局限”。
4. 重新组织段落：观点在前，理由与证据随后，每段只推进一个主题。
5. 复读全文，检查重复限定、无依据的加强词、习惯性谦辞及多余转折。

## 写法示例

以下用于说明表达方式，具体事实按原稿与证据核对。

| 可精简的表达 | 直接表达 |
| --- | --- |
| 这并不意味着整个素材学习闭环已经完成。 | EPUB 阅读已接入，选区学习和材料对话在后续切片实现。 |
| 本文无意提供完整的素材管理方案。 | 本方案定义 EPUB 导入、托管与阅读恢复。 |
| 这可能在一定程度上说明界面具有潜在可用性。 | 本轮浏览器验证覆盖导入、阅读和返回路径；实体触屏尚未验证。 |

“本文并不声称……”“当然也存在局限”“需要澄清的是……”等句式只有在承担必要区分时保留。明确的权限禁止、失败条件和未实现边界可以直接使用否定句。

## 研究与指标写作

修改研究材料时，围绕主要贡献组织内容。每项实验说明有效性、优势来源、其他解释或适用条件；影响核心结论的不利结果保留在相关章节。

某项指标落后时，说明比较条件及各指标结果。只发现相关关系时保持相关性表述；缺少验证时指出哪项主张缺依据。原因未知就保持未知，避免把局部结果推广为普遍缺陷。

按用户指定语言输出；未指定时沿用原稿语言。英文同样删去重复保留词，同时保留由证据决定的 `may`、`suggests` 或适用条件。
