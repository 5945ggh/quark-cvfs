# Quark VFS 实施草案 v0.1

供本地 coding agent 在新项目中作为实施说明使用。

- 调研日期：2026-10-12。
- 项目包名：`quark_vfs`；命令名：`quark-vfs`。
- 主要使用环境：本地 Codex；操作系统尚未指定，路径和进程管理保持跨平台，首次验收以用户实际电脑为准。
- 推荐技术：Python 3.12、uv、SQLite；Node.js 仅用于运行夸克官方传输 CLI。
- 当前阶段：架构与实施草案。此次只下载并静态阅读了官方材料，未执行官方运行时、未登录、未操作网盘。
- 本文不是已经可用的软件，不是新的 `SKILL.md`，也不表示兼容性门禁已经通过。

## 1. 目标、默认决策与交付边界

本项目为本地 Agent 提供一个结构化的云文件访问层，使其能够浏览夸克网盘、下载文件到本地工作区、上传工作产物、移动与重命名对象。用户愿意先授予全盘可见性，重点是方便使用和降低误操作造成的内容损失。

用户已进一步明确：多端“事实上能够取得这些文件”即可，各终端已有夸克网盘客户端；本项目不需要另外开发目录同步。跨设备文件可见性由夸克服务和既有客户端提供，包装层只负责 Agent 发起的具体文件操作。

首版采用“共用核心 + 受控 CLI + 薄 skill”的结构；stdio MCP 是推荐的工具接入形式，但必须先确认官方运行时在真实 Codex 启动链中正常识别环境。MCP 未通过验证时，CLI 与 skill 可以作为完整的首批交付，不能为了启用 MCP 而伪造 Agent 环境。

这里的 VFS 指统一的文件对象、路径解析与操作接口。Agent 需要使用 Python、编辑器、解压程序等本地工具时，先下载，再在本地处理，最后显式上传。本期不实现 FUSE 挂载、POSIX 文件句柄、随机读写、实时双向同步或远端代码执行。

| 事项 | v0.1 默认决策 |
| --- | --- |
| 云端读取范围 | 用户授权范围内全盘可见，实际 scope 以授权结果为准 |
| 操作范围 | 全盘可见不等于自动下载全盘；每次传输使用明确来源和目标 |
| 删除 | 不提供云文件永久删除；用专用目录保存移出的对象与恢复记录 |
| 上传、移动、下载冲突 | 默认 `fail`；显式选择 `keep_both`；暂不默认覆盖 |
| 替换原文件 | `archive_replace` 通过专项验证后启用，并明确其非原子性质 |
| 多端使用 | 通过各终端既有夸克客户端取得文件，不建设自己的同步引擎 |
| 长任务 | 当前已验证宿主进程存活时执行，退出后恢复或安全重启 |
| 权限与审批 | 不改 Codex 的审批配置，不新增逐文件人工确认门槛 |
| 依赖 | 使用外部安装的官方运行时，不将其捆绑进自研仓库 |

文中的“必须”是本项目的实现约束；关于夸克能力的事实用证据级别标注。产品建议不能反过来当作上游已经支持的事实。

## 2. 证据级别与已知能力

使用三种标签：

- **文档确认**：官方仓库、安装包中的文档明确描述；仍需基本烟雾验证。
- **静态观察**：从指定版本脚本看出的行为，没有在真实账号上执行。
- **待实测**：文档未给保证、实现有不确定性，或涉及宿主环境及并发语义。

本轮检视的官方仓库为 `quark-clouddrive/quarkclouddrive_offical`，提交为 `cba49a7e703d32607b1376375e3214fd8c63788f`，主 skill 版本为 1.0.24。安装包指纹见附录 A。仓库 README 和部分路径存在陈旧信息；重命名等部分引用文档只在 ZIP 中找到，下载行为主要依据脚本静态检查。实现者应以能力矩阵和实际安装版本为准。[S1][S2]

| 能力/限制 | 当前证据与实现影响 |
| --- | --- |
| CLI 入口 | `node <官方安装绝对路径>/scripts/quark-drive.cjs`；文档确认。不要依赖工作目录里的同名脚本 |
| Agent 环境门槛 | 真实环境识别是前置条件；Codex 检测依赖环境变量。MCP 子进程是否继承足够上下文待实测 |
| `resolve-agent` | 返回 `QK_AGENT_ID=codex` 这样的纯文本；静态观察，不走普通 NDJSON 解析器 |
| 认证 | 官方 CLI 管理 OAuth；文档描述全部文件授权，实际账号 scope 仍要检查 |
| 认证文件位置 | 偏向官方安装目录下的 `codex/`，不可写时存在回退 cwd 的路径；静态观察 |
| 完整目录枚举 | `browse --parent-fid ID --all` 获取完整直接子项，不递归；每页最多 100 项 |
| 枚举结果 | `result` 最多五条预览，完整结果在 Artifact JSONL；不能用预览决定完整批量操作 |
| 搜索 | `search --keyword ... [--parent-fid ...]`；搜索覆盖与排序由服务端决定，不能证明目录或全盘完整 |
| 文件身份 | 操作必须传完整 FID；末尾 `\|` 后的指纹仅用于本地去重，并加账号作用域 |
| 元数据 | `content_hash` 是夸克自定义的不透明标识，不能当作 MD5、SHA-1 或 SHA-256 |
| 上传 | 支持多个本地路径、目录递归、逐任务结果及续传入口；部分成功不得当成整批失败重做 |
| 移动/建目录 | `move` 单次最多 100 个 FID；`create-folder` 文档描述同名目录创建幂等 |
| 根目录 | FID 为字符串 `"0"`；省略目标目录不普遍等于根目录 |
| 下载 | 单文件下载有实现；结果不直接给 recordId；记录关联、续传与覆盖需专项验证 |
| 重命名 | 批处理支持 1–5000 项及批次撤回；撤回有服务端时间窗口，不是长期备份 |
| 云文件删除 | 本次列入适配的命令没有远端永久删除接口；`upload delete` 删除的是上传任务记录 |
| `stat` | 没有已文档化的同名 CLI 命令；包装层须通过已知父目录的新鲜枚举提供有限查询 |
| 原子性/并发 | 条件写入、原子替换、ID 在移动后稳定、碰撞行为均未获保证 |

以上主要来自官方 `SKILL.md`、`references/file-ops.md`、`file-search.md`、`file-upload.md`、`file-rename.md`、`auth.md`，以及包内 `scripts/quark-drive.cjs`。[S2]

## 3. M0 必须先解决的官方集成边界

### 3.1 真实运行环境

实现者先在用户正常启动的 Codex 会话中检查官方 CLI，然后分别检查“Codex → 包装 CLI → 官方 CLI”和“Codex → stdio MCP → 官方 CLI”。必须保存去敏后的识别结果、版本和失败原因，不能只凭入口文件存在就认定可用。

子进程继承当前真实环境，不复制或编造 `CODEX_ENV`、`AI_AGENT` 等身份字段，不修改官方检测代码，不借其他 Agent 身份绕过门槛。普通终端是否受支持目前未知；本期不建设脱离 Codex 的后台执行服务。

如果 MCP 启动方式丢失上下文，先检查正式配置和实际继承行为；只有官方支持的配置方式才能作为修复。仍不支持时，将 MCP 标记为不可用，保留受控 CLI 与 skill 路线。

### 3.2 官方完整 skill 与结构化文件接口

官方完整 skill 包含每轮用户输入前检查更新、通过 `--session-input` 传递用户原始提问用于质量追踪，以及内容理解任务调用上游 AI 等对话行为约定。[S2] 这比“提供上传下载工具”更宽。

本项目拟提供独立结构化接口，不直接复制整套对话路由策略。官方 skill 的对话指令不自动等于独立 CLI 的协议要求或服务条款；另一方面，“脚本不传某个参数仍能执行”也不能证明这种集成方式获得官方支持。M0 应查清独立 CLI 的支持范围，区分技术必需参数、认证与访问限制、对话行为建议和实际适用的服务要求；未查清的支持边界应如实记录。

包装层默认只传文件操作所必需的结构化参数，不自行收集整轮聊天。不得伪造身份、授权或会话信息，也不得绕过已确认适用的访问限制。如果经过核实，官方可用集成模式确实要求传原始请求，应明确说明哪些文本会传给夸克，再由用户选择是否采用该模式；不能静默扩大数据发送范围。未经确认，既不宣称可以规避该要求，也不把 skill 中的每条对话建议升级为实施阻塞。

服务端认证、授权范围、会员权益、配额和限流始终保留。工具结果应保留实际的上游 notice 与可读限制，并按最终确认的集成约定展示；不把业务失败伪装成成功，也不编造会员提示。

### 3.3 安装位置与版本

官方运行时放在固定、当前用户可写、不会被项目同步或提交到 Git 的位置，配置记录其绝对路径。禁止把整个官方包复制进自研源码或放进一个会随项目移动的虚拟环境。

启动前检查运行时及预期状态目录可写，避免认证文件静默落入当前仓库。若不能确认安全落点，返回可操作的诊断并停止认证写入。不要靠切换到项目根目录解决权限问题。

版本记录包含官方版本、入口文件指纹、包指纹及包装层协议版本。若上游更新是支持模式的要求，更新与业务命令串行；更新后重新做兼容性检查。若官方允许固定版本，则采用显式升级和回归验证。不能为了依赖可复现而擅自忽略上游要求。

## 4. 代码结构与依赖选择

建议用一个 Python 工程，不拆微服务。业务策略放在共用核心，CLI 和 MCP 都调用它。

| 模块 | 职责 |
| --- | --- |
| `config.py` | 运行时路径、本地目录、账号作用域、功能门禁 |
| `models.py` | FileRef、RemoteEntry、Job、Conflict 等稳定数据结构 |
| `provider/quark_cli.py` | 白名单命令构造、进程管理、真实环境继承 |
| `provider/protocol.py` | NDJSON、纯文本诊断、Artifact 解析、错误转换 |
| `provider/capabilities.py` | 版本能力矩阵与 M0 验证记录 |
| `core/catalog.py` | 完整枚举、路径解析、快照、有限 stat |
| `core/transfers.py` | 上传下载、staging、验证、官方记录关联 |
| `core/operations.py` | 建目录、移动、重命名、冲突检查 |
| `core/trash.py` | 回收清单、恢复、跨机器重建恢复索引 |
| `core/jobs.py` | 状态转换、逐项结果、中断恢复、同账号串行锁 |
| `storage.py` | SQLite 与本地原子文件写入 |
| `cli.py` / `mcp_server.py` | 两种入口，禁止各自重写文件语义 |

测试分为纯逻辑、录制协议样例、可选真实网盘集成三层。生产目录不混放测试账号状态；测试记录只保存去敏样例，不保存用户真实文件清单。

用 uv 管理依赖并提交 `uv.lock`。MCP SDK 必须选择实施时实际验证的版本：本轮官方 Python SDK 主线已经使用 v2 的 `MCPServer`，要求 Python 3.11+；不能照记忆直接粘贴旧版 `FastMCP` 示例。[S6] 本文不指定未经验证的导入路径。

不使用浏览器 Cookie 抓取、不新增未公开 HTTP 适配器、不提供万能 subprocess 或任意原始 API 工具。暂不实现 WebDAV 服务、FUSE、复制加速及在线内容理解。

## 5. 配置、状态与账号隔离

建议配置、状态、缓存使用用户本地数据目录；以下仅表示字段，不要求照抄机器路径：

```toml
[runtime]
node_executable = "/absolute/path/to/node"
official_entry = "/absolute/path/to/quarkclouddrive/scripts/quark-drive.cjs"
expected_version = "1.0.24"

[local]
state_dir = "/absolute/private/path/quark-vfs/state"
cache_dir = "/absolute/private/path/quark-vfs/cache"

[policy]
default_conflict = "fail"
follow_symlinks = false
max_active_transfers = 1

[features]
mcp_verified = false
archive_replace_verified = false
download_resume_verified = false
```

这些字段是本项目拟议接口，不是夸克或 Codex 的既有配置项。`false` 表示尚未通过门禁，不能由 Agent 为了消除报错而自行改成 `true`。

SQLite 保存账号作用域、目录索引、任务与回收索引。目录索引是缓存，不能作为永久事实。认证仍归官方 CLI 管理；包装层只记录非秘密的账号标识和认证状态，不复制 token，不读出凭证给模型。

不同设备分别登录，使用各自的 SQLite 和官方任务记录。禁止同步数据库、认证目录、日志、下载临时目录、官方安装包和上传任务状态来“克隆登录”。需要跨机器恢复的回收清单另存云端，格式独立于本地数据库。

日志默认记录操作 ID、动作、耗时和错误类别；参数中的用户文本、本地路径、下载链接等按需最小化。诊断包去掉 token、授权码、签名 URL、原始提示词和完整环境变量。不要把官方 stdout/stderr 无条件长期落盘。

## 6. 文件身份、路径、元数据与有限 stat

### 6.1 FileRef

所有涉及远端对象的接口接受两类引用，二者不能同时含糊生效：

```json
{"account": "default", "fid": "<完整FID>", "parent_fid_hint": "<完整父FID>"}
```

```json
{"account": "default", "path": "/课程/深度学习/笔记.md"}
```

路径解析从明确的根目录 `"0"` 或调用者提供的目录 FID 开始，逐级匹配直接子项的精确名称。无法唯一匹配时返回 `AMBIGUOUS_PATH`，附有限候选，不默认选第一个。特殊名称无法用路径无歧义表达时要求使用 FID。

所有上游参数原样传完整 FID。仅在同一账号的结果聚合时，按官方规则使用最后一个 `|` 后的非空原始尾串去重；不 trim、不转码，不把尾串发给 CLI。名字中的 `|` 没有身份含义。[S2]

### 6.2 RemoteEntry

统一条目至少包含完整 FID、父 FID、名称、类型、可选尺寸、可选时间、provider opaque hash、观测时间、来源快照。未知值使用 `null`，不能把缺少 size 当作零字节。

从遍历过程得到的路径可标记为 `resolved_path`；上游 `full_path` 的内部 pair 结构未完整定义，应保留原始值，不猜格式。上游的 `file_local_path` 也不是当前电脑可读取的路径。

`content_hash` 可以作为同一 provider 内的变化线索，但不是已知算法的校验值；不能据此认定两个 FID 是同一对象或删除“重复文件”。只有已验证语义后才用于内容相同性判断，仍须与对象身份分开。

### 6.3 vfs_stat 的真实边界

已知可靠父目录时，重新执行该父目录完整枚举，找到对象后返回 fresh 元数据。只给 FID 且没有位置线索时，可以使用本地索引提供明确标记的缓存信息，或返回 `LOCATION_UNKNOWN`。

在旧父目录中找不到对象，并不能证明已被删除：它可能被外部客户端移动、权限改变或暂不可见。若没有受支持的定位方法，返回 `LOCATION_UNKNOWN`，不要杜撰 `stat`、`file-info` CLI 或调用未公开 HTTP。

显式授权范围的递归重建索引可以帮助重新定位，但成本和覆盖范围必须可见；不能为了查询一个 FID 默认扫描全盘。搜索能提供候选，搜索为空不能作为不存在证明。

## 7. CLI 适配协议与完整枚举

以参数数组调用固定 Node 入口，禁止 `shell=True` 和拼接用户字符串成为 shell 命令。包装接口只接受明确字段，不接受 `raw_args`、任意 endpoint 或命令片段。

命令类型分别处理：

1. `resolve-agent` 等诊断纯文本按专用解析器处理。
2. 普通命令逐行解析 NDJSON，收集 `progress`、`list`、`result`、`artifact`。
3. 不假设最后一行一定是业务 result；浏览与搜索常在 result 后输出 Artifact。
4. 退出码、最终业务结果和逐项结果共同判断成功；非零结果可能已经有部分文件完成。
5. 官方返回的非空 notice 保留为独立字段，不覆盖业务状态。

完整枚举固定使用明确父 FID 和 `--all`。默认分支读 `artifact.data.file_path`；若使用已验证的 `--task-dir` 分支，则按文档从 `result.data.file_path` 读取，不能同时等待不存在的 Artifact。

读取前验证返回文件位于本次调用允许的本地输出范围，逐行解析完整 JSONL，核对读入条数和必要字段；错误、文件丢失、协议异常或未完整分页一律不发布“完整快照”。五条预览只用于界面摘要。[S2]

官方 CLI 内部处理 cursor，外部没有通用 cursor 参数。`vfs_list` 若需向 MCP 分页，应先完成一次枚举，再对本地不可变快照分页，返回 `snapshot_id + next_page_token`。该 token 只能定位本地快照，不冒充上游 cursor。

快照带 `started_at`、`finished_at`、`scope`、`complete`。枚举完成不等于服务端提供了某一瞬间的一致快照；扫描过程中外部变化仍可能存在。用于写操作的对象在执行前重新检查。

递归枚举逐目录进行，记录失败目录与已知范围。搜索工具单独工作，不用“所有关键词结果汇总”构造全盘清单，也不通过机械拆分搜索来规避服务限制。

## 8. 公共工具契约

所有工具返回结构化对象，包含 `ok`、`operation_id`、`data`、`warnings`；失败含稳定错误码和 `retryable`。长任务返回包装层 `job_id`，不能混同官方 recordId。

| 工具 | 主要输入 | 输出与默认语义 |
| --- | --- | --- |
| `vfs_status` | 可选 account、refresh | 安装/认证/真实环境、版本、能力门禁、当前任务概况 |
| `vfs_list` | directory、page_size、本地 page_token | 一次完成枚举产生的直接子项快照；默认不递归 |
| `vfs_stat` | FileRef、fresh | 有限定位查询；无法确认外部移动时返回 LOCATION_UNKNOWN |
| `vfs_search` | keyword、可选 directory/type | 服务端搜索结果，明确范围不保证覆盖 |
| `vfs_mkdir` | parent、name 或受控相对路径 | 明确父目录下建目录，返回实际 FID |
| `vfs_upload` | local_paths、remote_parent、conflict | 先检查本地范围，再上传；默认 fail |
| `vfs_download` | source、local_target、conflict | 单文件或包装层枚举的目录任务；默认 fail |
| `vfs_move` | sources、target_parent、expected | 移动前检查，按最多 100 项切批，逐项记录 |
| `vfs_rename` | items、expected | 确定的旧名→新名映射，不接收模糊自然语言规则 |
| `vfs_trash` | sources、reason | 创建独立恢复单元，记录原位置后移动 |
| `vfs_restore` | trash_entry、可选 destination、conflict | 默认恢复原位置；冲突不覆盖 |
| `vfs_jobs` | action=list/get/resume、job_id | 查询或显式恢复；若提供 cancel，仅暂停并留记录 |

CLI 对应这些能力，同时提供 `doctor`、`auth` 等本地管理入口。`auth` 引导官方认证；不经 MCP 收集密码，不要求用户把长期凭证写进 skill。

`expected` 是包装层预期状态，不声称服务端提供 CAS。可包含已观测的完整 FID、父 FID、名称、尺寸、时间、opaque hash 和快照 ID。执行前不符合预期则返回 `PRECONDITION_FAILED` 或 `SOURCE_CHANGED`。

错误码至少覆盖：`AUTH_REQUIRED`、`UNSUPPORTED_AGENT_CONTEXT`、`UNSUPPORTED_CAPABILITY`、`AMBIGUOUS_PATH`、`LOCATION_UNKNOWN`、`DESTINATION_EXISTS`、`PRECONDITION_FAILED`、`PARTIAL_FAILURE`、`RATE_LIMITED`、`QUOTA_EXCEEDED`、`PROTOCOL_ERROR`、`OUTCOME_UNKNOWN`。

`read_text`、云内复制、分享链接、上游 AI 内容理解、任务记录删除、任意原始调用后置或不做。工具越少，语义越容易保持一致。

## 9. 任务日志、状态转换与恢复

SQLite 至少需要 `jobs`、`job_items`、`catalog_snapshots`、`trash_index`。不必引入消息队列服务；进程内调度加持久化记录足够启动。

任务状态建议为：

```text
planned
running
paused
needs_reconciliation
succeeded
partial
failed
```

每一步开始前记录意图，确认结果后记录事实。任务记录包括动作、账号、来源与目标、预期状态、staging 路径、官方任务标识、验证等级、逐项结果和最近错误。总任务失败不抹掉已成功项。

`needs_reconciliation` 用于请求可能已经生效、但未收到可靠回应的情况。恢复先查已知位置、官方记录及远端临时对象，再决定继续；禁止网络错误后一律重发有副作用的命令。

M1 默认同账号传输串行，并给任务加本地进程锁，减少官方状态竞争。这只能协调本机包装层，不能锁住另一台机器、官方客户端或服务端。

官方重命名等命令有自己的 batch、记录文件、可重试错误及限流处理规则，应逐命令遵守；不要套用通用指数重试覆盖所有操作。限流、权益次数类失败不能通过换 batch 或重建任务规避。

MCP 存活时，任务可在该进程内继续；进程退出时尽量暂停并记账。无法确认暂停成功的记录在下次启动转入待核对。首次恢复不能仅因为本地状态写着 running 就宣称远端仍在执行。

## 10. 上传、下载与冲突策略

### 10.1 本地路径检查

上传前列出真正将上传的文件。默认不跟随符号链接；只处理明确选择的本地路径，不因进入仓库就递归上传整个仓库。默认排除本项目认证、状态和临时目录；对 `.env`、密钥、凭证及常见秘密文件做显式提示或排除记录。

排除列表必须可见、可配置，不静默忽略用户指定的数据。是否排除 `.git`、依赖目录和构建产物由本次上传选项决定；普通数据目录不应被套用隐形的代码仓库规则。源文件在传输期间变化时，返回 SOURCE_CHANGED，不宣称已上传当前版本。

下载检查远端名称与本地文件系统的兼容性，包括路径逃逸、NUL、大小写冲突和 Unicode 名称冲突；不把两个云文件悄悄合并到一个本地路径。必要时返回命名冲突，由用户显式选择映射。

### 10.2 上传

官方上传入口支持目录递归，但包装层只有在本地清单与链接策略通过验证后才直接传目录；否则按清单创建目录并逐文件上传。所有调用显式提供由 FileRef 解析出的目标父 FID，不依赖默认保存位置。

收集每个 `list` 行的 recordId、fileId 与成功/失败信息，最终 result 只做总体汇总。部分成功时只处理未完成项，不重新上传整批。[S2]

避免覆盖的增强路径是先上传到本操作独享的远端 staging，再检查正式目标并移动过去；但移动碰撞行为仍必须实测。即使先检查目标不存在，没有条件写入时仍可能与外部客户端发生竞争，不能宣称严格的 create-if-absent。

`keep_both` 生成明确的新名称，保留原扩展名，并在返回值中给出最终名称。名称应在目标目录重新检查；若仍冲突则停止或重新计划，不无限循环试名字。

上传续传使用记录中的真实 recordId，先检查本地源路径与指纹。官方任务失效或能力未验证时，保留已知状态并安全重启该文件，不伪装为从原偏移继续。

### 10.3 下载：必须隔离 staging

官方 `download --fid <ID> --output-dir <DIR> [--overwrite]` 按单文件工作。包装层每个文件任务创建独立的本地 staging 目录，正式目标绝不直接传给官方 `--overwrite`。

静态代码中覆盖路径存在 `r+` 打开且未确认截断的风险：新文件比旧文件短时可能遗留旧尾部。因此恢复后必须检查实际长度；可信预期 SHA-256 可用时再比对哈希。自己对下载结果计算 SHA-256 只得到本地指纹，没有可信预期值时不能声称校验通过。

成功结果提供 fileName/filePath，却不直接提供 recordId。首版在同账号串行条件下，通过 `download list` 前后差异和已经实测的稳定字段关联任务；只有唯一匹配才能登记。存在多个候选时进入待核对，不猜测。

`download list` 的 downloadedSize 在本版本静态代码中为固定零，不能当作真实进度或断点位置。必要时返回进度未知，不用虚假的百分比改善界面。

续传按官方逻辑由 output-dir 与原始名称重建路径，因此记录并保持同一 staging 目录、原始名称和真实 recordId。远端对象已变化、记录失效或无法确认关联时，不继续拼接旧内容；保留诊断后安全重启。

下载完成后核验返回路径确实属于该 staging，检查长度与指纹，再提交到本地正式目标。提交前再次检查目标是否出现或变化，默认拒绝覆盖。正式提交还须使用经过平台验证的 no-replace 方法，不能仅靠“先检查不存在”后调用可能覆盖的 rename 或 os.replace；优先让 staging 与目标位于同一文件系统，使用具备目标存在即失败语义的发布操作。目录下载由包装层完整枚举后编排多文件任务，报告遗漏和失败，不能把部分目录称作完整下载。

### 10.4 验证等级

返回值明确区分 `size_checked`、`local_fingerprint_recorded`、`trusted_hash_verified`。记录“传输完成”和“内容已用可信摘要验证”是两件事。

本地文件上传前的 SHA-256 可以成为后续下载的可信预期值，但必须可靠绑定到确切远端对象和版本，并确认上传前后源文件未变化。外部未知文件、opaque content_hash 或路径相同都不足以建立这种绑定。

## 11. 移动、重命名、回收与恢复

### 11.1 独立移动与重命名

移动按目标目录新鲜清单检查碰撞，单次最多 100 个对象；跨批次不是整体事务。目录不能移入自身子树，递归关系无法确认时停止。批量中断要保留已移动对象的实际目标。

重命名由包装层生成明确 items 和本地记录文件，依官方命令提交并保存真实 batch 记录。不同来源目录的同名文件不能仅凭名称匹配。上游 1–5000 项能力不是首版必须用满的容量；优先处理可检查的小批次。

`rename-revert` 是有时间窗口的批次撤销，记录文件与 batch 必须对应真实请求。它不替代回收目录，也不能被描述为随时可撤销。v0.1 工具层可以先不暴露独立 revert，保留恢复诊断入口。[S2]

### 11.2 云端回收目录

初始化时在用户选定的明确位置建立 `QuarkVFS-Trash`，可另建 `QuarkVFS-Staging`。名称可配置；必须记录创建后的真实 FID。两个目录仍可手动浏览，但默认排除在普通递归下载或整理任务之外，避免再次处理回收对象。

每个回收操作使用 UUID 形式的 op_id，每个源对象有独立子目录，避免来自不同父目录的同名文件撞在一起。目录对象可整体移动，保留内部层级。

最小远端恢复清单如下：

```json
{
  "schema_version": 1,
  "operation_id": "<uuid>",
  "created_at": "<UTC timestamp>",
  "reason": "user_trash",
  "entries": [{
    "original_fid": "<完整FID>",
    "original_parent_fid": "<完整父FID>",
    "original_name": "报告.pdf",
    "original_path_hint": "/资料/报告.pdf",
    "trash_container_fid": "<完整FID>",
    "expected_size": 12345,
    "provider_content_hash": null
  }]
}
```

先保存本地意图并上传不可变清单，确认清单可读取后才移动源对象。移动完成后上传单独的完成事件，记录实际观察到的 FID 和位置；避免反复覆盖同一份 manifest 依赖未知覆盖语义。

事件缺失不能直接判断移动失败。恢复先核对原位置与回收容器，再决定任务完成度。远端 manifest 和事件都是数据，不包含可执行命令；解析时验证 schema、账号范围和引用对象，不能按其中的任意本地路径写文件。

本地数据库遗失或换设备时，可以从远端恢复清单重建回收索引。恢复能力不依赖原电脑的上传任务记录。清单和 payload 的实际存在需要一起验证，不能只有一个名字就显示“可恢复”。

### 11.3 恢复

优先使用原父 FID 定位；若其路径变化，展示新的恢复位置。无法确认父目录存在或可用时，要求显式恢复目标，不能凭旧字符串猜测对象。

原名称被占用时默认拒绝，允许显式 `keep_both` 生成新名称；恢复不顺手覆盖新文件。完成后记录实际位置和内容验证等级，保留恢复历史，不自动永久删除清单。

回收目录占用容量，没有自动清空、TTL 清除或“任务结束后删掉旧版本”。用户以后可在官方客户端自行处理空间，工具可以报告容量与回收量，但不提供不可逆清空接口。

### 11.4 可选 archive_replace

只有在 staging、移动碰撞、恢复链路和内容验证均通过专项验收后启用：上传新版本至独立位置，复核原对象，将旧对象移入回收目录，再将新对象就位。

这是可恢复的多步操作，不是原子替换。中间可能暂时没有正式路径；异常时先核对，再恢复旧对象或完成新对象移动。没有 CAS 时依然存在跨设备竞争窗口，不能承诺所有外部更新都被保存。

## 12. 其他客户端的并发变化

不开发同步引擎，仍然需要处理其他夸克客户端可能修改同一个对象的事实。移动、重命名和可选替换前，使用新鲜目录信息检查来源与目标；名称、父目录、尺寸或已知版本线索变化时停止受影响项，返回冲突。

批量操作可生成本地预览，展示将处理的完整对象、目标、冲突和字节估算。预览用于一致性检查和审阅，不新增逐文件人工审批。用户已明确授权范围和操作时，Agent 检查后可以继续执行；扩大范围或改变冲突策略时再讨论。

逐项记录实际结果。当前批次中部分成功，不允许靠“重跑整批”补救；先核对已生效对象，再处理失败项。内容和位置无法确认时保留对象，返回 OUTCOME_UNKNOWN 或 LOCATION_UNKNOWN。

缺少服务端条件写入时，前置复核仍不能消除检查与写入间的竞争窗口。保留已有内容、使用独立 staging、默认拒绝碰撞可以降低风险，但不能承诺任意客户端同时修改时强一致。本地锁也不能代表跨设备锁。

## 13. Codex 接入方案

Codex 官方支持通过配置声明本地 stdio MCP，配置包含 `mcp_servers` 下的 `command`、`args` 和 `enabled_tools` 等字段；skill 可放在 `~/.agents/skills/quark-vfs/SKILL.md`。[S3][S4] 实际配置以本机 Codex 版本和官方文档核对为准。

以下是拟议示例，只有 M0 验证通过后才安装；不要覆盖用户已有配置：

```toml
[mcp_servers.quark_vfs]
command = "/absolute/path/to/quark-vfs"
args = ["mcp"]
enabled_tools = [
  "vfs_status", "vfs_list", "vfs_stat", "vfs_search",
  "vfs_mkdir", "vfs_upload", "vfs_download",
  "vfs_move", "vfs_rename", "vfs_trash", "vfs_restore", "vfs_jobs"
]
```

使用经过安装的入口或虚拟环境绝对路径，避免由临时 cwd 决定模块版本。stdio 正常输出只承载 MCP 协议；包装层日志写 stderr 或私有日志文件，官方子进程 stdout 必须由适配器消费，不能直接混入 MCP 通道。

薄 skill 只说明触发场景、文件引用、默认冲突策略、先下载再本地处理、长任务状态、回收/恢复、已知能力边界，以及 MCP 不可用时的 CLI 入口。不复制 token、设备身份、业务状态或整套官方 skill 文本。

stdio 工具调用不自动等同于 Codex shell 沙箱内的命令，不能假设 shell 审批和网络限制会覆盖所有 MCP 行为。[S5] 包装层自己限制工具种类和路径处理，但不改用户审批策略，也不请求整体关闭安全控制。

MCP 未通过真实环境门禁时，文档应给出 CLI + skill 的工作方法与准确诊断；不注册一个看似可用、实际全部报环境错误的服务。

## 14. M0–M3 实施顺序与完成标准

### M0：确认可支持的集成方式

完成版本盘点、静态阅读和真实 Codex 环境识别；核实独立 CLI 的公共参数/更新约定；固定可写安装位置；由用户完成官方授权并检查 scope。使用单独测试目录和可再生文件验证基本能力。

专项验证至少包括：超过一页的目录枚举、FID 传递、移动/重命名后的身份、撞名处理、上传部分成功、下载 recordId 关联、同 staging 续传和短文件覆盖尾部问题。所有测试对象最后移入自己的回收目录，不调用永久删除。

交付 `CAPABILITIES.md`、`COMPATIBILITY.md`、去敏协议样例和未通过项。门禁未通过的能力明确关闭；独立 CLI 集成不受支持时先报告，不能绕过继续。

### M1：可用文件核心、受控 CLI 与薄 skill

实现状态、枚举、路径解析、有限 stat、搜索、建目录、上传下载、移动重命名、回收恢复和 jobs。具备结构化输出、逐项结果、任务恢复及默认 fail/keep_both。

一并编写薄 skill，说明如何通过 CLI 使用这些能力，不等待 MCP 接入。完成标准：Agent 在真实 Codex 会话中能浏览目录，往返处理一个文件，完成回收与恢复，并在中断后得到可信状态。此时已经可以作为额外云存储使用。

### M2：经过验证的可选 MCP

为同一核心增加适配层和安装说明，验证真实上下文继承、stdio 输出、认证失效、进程退出与重连行为。MCP 不可用时交付 CLI + skill，记录限制和以后复查的方法。

完成标准：Codex 能发现工具并完成同一往返操作；工具结果不泄露凭证，不声称后台任务脱离宿主仍在继续。

### M3：按实际需求选择的轻量增强

可选方向包括有字节上限的文本读取、可检查的云内复制和更好的传输进度。先确认上游能力再启用；若复制实际需要下载再上传，应说明实际过程和成本，不能伪称原生云端复制。`archive_replace` 也作为独立门禁能力，通过验证后才启用。

本阶段不是首版完成条件，不预先承诺所有增强。FUSE、同步引擎、常驻任务、自动清空回收站和细粒度权限系统均不列入实施安排。

## 15. 必要验收测试

测试应针对具体风险，不为每层薄转发写重复实现的测试。

| 场景 | 必须观察到的结果 |
| --- | --- |
| `resolve-agent` 纯文本 | 解析正确；不报假 NDJSON 错误 |
| 目录超过 100 项 | 完整读取 Artifact；非五条预览；本地分页不遗漏 |
| 某页/Artifact 失败 | 不生成完整快照，不据此推断删除 |
| 完整 FID 含 `\|` | 操作原样传递；去重指纹不跨账号混用 |
| 同名、中文、日文、大小写差异 | 精确定位；无法映射时冲突，不覆盖 |
| 外部移动后的 stat | 能确认才给 fresh，否则 LOCATION_UNKNOWN |
| 上传部分成功 | 保存成功项，恢复只处理未完成项 |
| 下载结果没有 recordId | 唯一关联才续传；歧义进入待核对 |
| 下载中断与恢复 | 同 staging 恢复，结果尺寸正确，正式目标完整 |
| 大文件覆盖为短文件的专项样例 | 无旧尾部；没有验证前不启用该路径 |
| 上传/移动响应丢失 | 先核对结果，不盲目重复副作用 |
| 旧版本入回收后进程退出 | 可找回旧内容，也能定位未就位的新内容 |
| 恢复原路径已有文件 | 默认拒绝覆盖；keep_both 保留双方 |
| 本地数据库丢失 | 从远端清单恢复索引与对象位置 |
| 其他客户端在预览后修改对象 | 已检测的变化使操作失效，不悄悄扩大覆盖范围 |
| 云文件被其他客户端移走 | 位置未知时明确报错，不自动重新上传或猜测对象 |
| 认证过期、MCP 退出 | 状态诚实可恢复；不泄露认证数据 |

协议单元测试使用经去敏的样例；文件决策使用临时目录；真实网盘测试仅对专用目录运行。网络故障可注入到适配器边界，避免为了测试中断破坏其他用户任务。

真实并发测试可以发现风险，不能证明没有 CAS 的协议获得强一致。测试报告必须区分“此样例通过”和“服务端提供保证”。

## 16. 能够承诺与不能承诺的事情

在所有入口经过包装层的范围内，可以承诺：不主动调用云文件永久删除；默认拒绝已检测到的覆盖；任务有逐项记录；回收包含恢复信息；已检测到的冲突不会被静默当作成功；认证数据不被主动同步。

不能据此承诺：Agent 通过其他 shell 工具也无权删除；所有客户端任意并发都不丢更新；所有传输都能文件内断点续传；批量移动与替换是原子的；本地 SHA-256 等于已经验证云端内容；退出 Codex 后任务一定继续。

本项目应把这些边界直接体现为能力字段、任务状态和错误码，而不是只在文档末尾写一句免责说明。未知能力保持关闭或返回未知，待实测结果形成后再更新。
