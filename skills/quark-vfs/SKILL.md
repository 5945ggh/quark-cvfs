# Quark VFS

使用安装好的 `quark-vfs` CLI 和用户配置的账号作用域。所有文件语义由共用核心执行；不要绕过它调用未公开 HTTP、复制凭证或拼接任意官方 CLI 参数。

## 入口

每次使用明确的配置绝对路径：`quark-vfs --config /absolute/config.toml <command>`。安装入口和本机配置由项目 README 或安装时提供的本机说明确定；不要从工作目录搜索同名可执行文件。

先通过 `status` 查看本地条件。默认状态查询只读本地信息；需要登录探活时使用 `status --refresh`，需要只读核验云端 marker 时使用 `status --verify-scope`，两项可以组合。若授权已过期，说明结果并用 `auth login` 引导浏览器授权，不收集密码或 token。scope 验证为 `unavailable` 表示尚未完成验证；验证失败时停止文件操作，不自动重绑定。

命令和 JSON 引用示例见 [CLI 工作流](references/cli.md)。作用域及回收恢复规则见随 skill 安装的[恢复参考](references/recovery.md)。以当前 `--help` 和能力矩阵为准，不调用未开放的能力。

## 当前可用范围

本机已开放文件/目录上传下载、枚举、有限 stat、全局候选搜索、建目录、移动重命名、回收恢复与持久化 jobs。单文件传输的包装层保护上限为 128 MiB；该容量的本地边界已验证，上游 128 MiB 往返尚未实测。父目录过滤搜索在当前环境返回上游错误，不能静默改为全局搜索。MCP、替换及文件内断点续传尚未开放。`tree` 已实现；调用方式与 partial 结果约束见 [CLI 工作流](references/cli.md#tree)。

## 文件工作流

- 浏览使用完整目录快照及本地分页。只有 `complete: true` 才表示完整底层快照；多页结果继续读取 `next_page_token`。搜索只给候选，搜索为空不能证明文件不存在；预览也不能作为完整批量清单。
- 使用 `tree` 时明确给出根引用和所需深度；读取 partial 结果后，可按未读分支的完整 FID 显式继续浏览，并根据需要调整预算，不自动重跑整盘。
- 路径逐级精确解析；歧义时使用完整 FID。保留列表提供的父目录提示。上传、建目录回执 ID 与枚举 FID 可能属于不同表示，不能截断或猜测转换。
- 处理内容时先下载到明确本地目标，用本地工具加工，再显式上传产物。上传范围限于用户选定路径；将被排除的凭证、状态目录或链接如实告知用户。
- 冲突默认 `fail`。只有用户明确选择或本次任务已授权保留双方时才用 `keep_both`；不自动改成覆盖，也不提供永久删除。
- 回收使用 `trash` 的恢复清单和记录；恢复使用对应 operation/entry 标识。必须保留 `QuarkVFS-<UUID>` 管理根、marker，以及配置的回收根和正式回收数据。作用域或回收异常时停止操作，按[恢复参考](references/recovery.md)处理。
- `jobs` 可离线查询旧 account alias 的本地历史，但不核对云端；`--resume` 仍要求 scope 验证通过。缺少数据库不代表没有未完成任务。
- 长操作的实际状态以持久化 job 和逐项结果为准。已成功项不重复执行；结果未知时先核对，不能重跑整批。`jobs --resume` 只执行已实现的安全恢复策略，不能把它描述为已验证的文件内断点续传。

对已明确授权的文件操作按这些默认策略继续，不新增逐文件确认。扩大文件范围、改变冲突策略或无法确认目标时，再获取必要信息。MCP、原子替换和跨设备强一致只有能力记录明确通过后才可声称支持。
